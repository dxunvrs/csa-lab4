# Шулай Роман Юрьевич, P3215

- Архитектура компьютера
- Лабораторная работа №4
- Вариант: `alg | risc | harv | hw | trap | port | cstr | vector | alg3`
- Без усложнения

## Язык программирования

### Синтаксис
```
program             ::= { top_level_decl }

top_level_decl      ::= fun_decl
                      | handler_decl
                      | top_level_stmt

fun_decl            ::= "fun" identifier "(" [ param_list ] ")" block
handler_decl        ::= "handler" integer block

top_level_stmt      ::= global_var_decl
                      | assignment_stmt
                      | if_stmt
                      | while_stmt
                      | out_stmt
                      | expr_stmt

param_list          ::= identifier { "," identifier }
block               ::= "{" { statement } "}"

statement           ::= var_decl
                      | assignment_stmt
                      | if_stmt
                      | while_stmt
                      | return_stmt
                      | out_stmt
                      | expr_stmt

global_var_decl     ::= "var" identifier "=" global_initializer ";"
global_initializer  ::= [ "-" ] integer | char_literal | string_literal | arr_alloc
var_decl            ::= "var" identifier "=" ( expr | arr_alloc ) ";"
assignment_stmt     ::= lvalue "=" expr ";"
lvalue              ::= identifier [ "[" expr "]" ]

if_stmt             ::= "if" "(" expr ")" block [ "else" ( block | if_stmt ) ]
while_stmt          ::= "while" "(" expr ")" block
return_stmt         ::= "return" [ expr ] ";"
expr_stmt           ::= expr ";"

expr                ::= logic_or_expr

logic_or_expr       ::= logic_and_expr { "||" logic_and_expr }
logic_and_expr      ::= equality_expr  { "&&" equality_expr }
equality_expr       ::= relational_expr { ( "==" | "!=" ) relational_expr }
relational_expr     ::= additive_expr   { ( "<" | "<=" | ">" | ">=" ) additive_expr }
additive_expr       ::= mult_expr       { ( "+" | "-" ) mult_expr }
mult_expr           ::= unary_expr      { ( "*" | "/" | "%" ) unary_expr }

unary_expr          ::= ( "-" | "!" ) unary_expr | primary_expr

primary_expr        ::= integer
                      | char_literal
                      | string_literal
                      | identifier [ "[" expr "]" ]
                      | fun_call
                      | in_expr
                      | "(" expr ")"

fun_call            ::= identifier "(" [ arg_list ] ")"
arg_list            ::= expr { "," expr }

arr_alloc           ::= "arr" "(" integer ")"
in_expr             ::= "in" "(" integer ")"
out_stmt            ::= "out" "(" integer "," expr ")" ";"

identifier          ::= ( letter | "_" ) { letter | digit | "_" }
integer             ::= digit { digit }
string_literal      ::= '"' { string_char | escape } '"'
char_literal        ::= "'" ( char | escape ) "'"
string_char         ::= <ASCII-символ, кроме двойной кавычки, обратной косой черты и перевода строки>
char                ::= <ASCII-символ, кроме апострофа, обратной косой черты и перевода строки>
escape              ::= "\\" ( "n" | "t" | "0" | "\\" | '"' | "'" )

letter              ::= "a" ... "z" | "A" ... "Z"
digit               ::= "0" ... "9"
```

- Размер `arr(N)` - положительный целочисленный литерал
- Номер входного порта и обработчика - от 1 до 131071 (`2^17 - 1`, максимум знакового 18-битного поля). Единственный выходной порт имеет номер 1
- `return` разрешен только внутри функций, в том числе в их вложенных блоках. В обработчиках и основном коде запрещен
- Пробелы, табуляция, переводы строк и комментарии пропускаются при разборе

### Ключевые слова

- `var` - объявление переменной
- `if (expr) {}`, `else {}` - условные переходы
- `while (expr) {}` - цикл
- `out(port, value)` - вывод
- `in(port)` - ввод
- `arr(N)` - статически выделить память под массив из N слов, только в инициализаторе `var`
- `handler N {}` - обработчик прерывания
- `fun name (arg1, arg2, ...) {}` - объявление функции
- `return` / `return expr` - возврат из функции

### Семантика

#### Стратегия вычислений

- Код выполняется последовательно
- В основном коде и локальных блоках переменные объявляются до использования. Функции и обработчики имеют доступ ко всем глобальным переменным независимо от положения объявления
- Передача аргументов в функции происходит по значению - передается копия значения аргумента (для чисел - само число, для массивов и строк - копия указателя)
- Выражения вычисляются слева направо с учетом приоритета операторов (`() -> -, ! -> *, /, % -> +, - -> <, <=, >, >= -> ==, != -> && -> ||`)
- Бинарные операторы одного приоритета вычисляются слева направо. `&&` и `||` используют короткое замыкание
- При присваивании элементу массива сначала вычисляется адрес элемента, затем правая часть
- Начальные значения глобальных переменных записываются в память до запуска. Вычисления и вызовы функций для них выполняются отдельными присваиваниями в основном коде

#### Описание семантики

- Для переменных, объявленных на верхнем уровне, глобальная область видимости
- Для аргументов функций и локальных переменных блочная область видимости
- Повторное объявление в одной области запрещено, во вложенном блоке разрешено затенение внешней переменной
- Параметры и внешний блок функции образуют одну область. Локальное имя доступно после вычисления инициализатора
- Имена чувствительны к регистру. Ключевые слова нельзя использовать как имена, имена функций нельзя затенять переменными
- Названия переменных начинаются с латинской буквы или нижнего подчеркивания, в названии переменных также могут содержаться цифры
- Бестиповая модель данных
- Значения - 32-битные слова в дополнительном коде. Переполнение арифметики обрезается до 32 бит, сравнения выполняются со знаком
- Диапазон числовых литералов соответствует знаковому 32-битному слову: от `-2^31` до `2^31 - 1` (от -2147483648 до 2147483647). Числа только десятичные, ведущие нули разрешены
- Деление округляется к нулю, остаток имеет знак делимого. `-2147483648 / -1` дает `-2147483648`, остаток - 0. Деление на ноль - ошибка выполнения
- Ноль - ложь, ненулевое значение - истина. Сравнения и логические операции возвращают 0 или 1
- Нет констант
- Литералы: числа, строки и ASCII-символы
- Escape-последовательности: `\n`, `\t`, `\0`, `\\`, `\"`, `\'`. Неизвестная последовательность, не-ASCII символ и перевод строки внутри литерала запрещены
- Организация массивов: выделение памяти через `arr(N)`, доступ к элементу через `a[i]`
- Строки изменяемы, завершаются нулевым словом. Сравнение строк и массивов через `==` сравнивает указатели, не содержимое
- Проверок границ отдельных массивов нет. Арифметика указателей обрезается до 32 бит
- Вызовы функций до определения и рекурсия разрешены. Число аргументов должно совпадать с числом параметров
- `return;` и достижение конца функции возвращают 0. Обработчик завершается только при достижении конца тела
- `out` не возвращает значение. Присваивание не является выражением. `break`, `continue`, вложенные функции и самостоятельные блоки не поддерживаются
- Разделитель - `;`
- Комментарии - `//`

## Организация памяти

- Архитектура: Гарвардская (память команд и память данных разделены)
- Размер машинного слова: 32 бита
- Порядок байт: Little-Endian
- Память команд:
  - Однопортовая, доступна только для чтения
  - Адресация побайтовая, инструкция занимает 4 байта
- Память данных:
  - Однопортовая, доступна на чтение и запись
  - Адресация побайтовая
  - Размер - 4 КБ. Доступ к словам только по адресам, кратным 4

### Регистровый файл

1. Регистры общего назначения (16 регистров по 32 бита):
  - `r0` (`zero`) - всегда ноль, запись игнорируется
  - `r1 - r4` - аргументы функций, `r1` также результат (caller-saved)
  - `r5 - r8` - временные значения (caller-saved)
  - `r9 - r12` - сохраняемые вызываемой функцией регистры (callee-saved)
  - `r13` - Stack Pointer - указатель на вершину стека
  - `r14` - Frame Pointer - указатель на начало стекового фрейма
  - `r15` - Return Address - адрес возврата
2. Аппаратные регистры:
  - `PC` - Program Counter - счетчик адреса текущей инструкции
  - `EPC` - Exception PC - регистр для сохранения `PC` при прерывании
  - `IE` - флаг разрешения прерываний

Регистровый файл имеет два порта чтения и один порт записи. При запуске `PC`, `EPC`, `IE` и регистры равны 0, кроме `SP = 0x1000`.

### Карта памяти


```text
       Instruction Memory (Байтовая)              Data Memory (Байтовая, 4 КБ)
      +------------------------------+          +------------------------------+ 0x0000
0x00  | JMP <start>                 |          | Секция статических данных    |
0x04  | JMP <handler 1>             |          | (.data):                     |
 ...  | ...                         |          |  - Глобальные переменные     |
4*N   | JMP <handler N>             |          |  - Буферы arr(N)             |
      +------------------------------+          |  - Строки cstr (Null-term)   |
      | Исполняемый код программы:   |          |  - Числовые константы        |
      |  - Функции                   |          |                              |
      |  - Обработчики handler       |          +------------------------------+
      |  - Основной поток (main)     |          |                              |
      |                              |          |       Свободная память       |
      |                              |          |              |               |
      |                              |          |              v               |
      |                              |          |                              |
      |                              |          |              ^               |
      |                              |          |              | (растет вниз) |
      |                              |          | Стек вызовов (.stack):       |
      |                              |          |  - Адреса возврата           |
      |                              |          |  - Сохраненные регистры      |

```

Таблица содержит стартовую запись и записи до максимального номера обработчика. Пропуски заполнены `HALT`. Без обработчиков таблица занимает одно слово. Исполняемый код размещается после таблицы.

### Способы адресации

1. Регистровая - операнды берутся из регистрового файла
2. Непосредственная - операнд находится в теле инструкции (18-битное поле)
3. Базовая со смещением - адрес вычисляется относительно какого-либо регистра + offset
4. Относительная - `PC + offset`
5. Абсолютная - прямой переход

### Отображение программы и данных на процессор

- Константы и литералы:
  - Числа, помещающиеся в знаковое 18-битное поле (от `-2^17` до `2^17 - 1`, то есть от -131072 до 131071), загружаются через `ADDI`. Остальные размещаются в `.data` и загружаются через `LW`
  - Строковые литералы (`cstr`) размещаются в `.data`: один ASCII-символ на 32-битное слово, в конце нулевое слово
  - Каждое вхождение строкового литерала получает отдельный блок, одинаковые строки не объединяются
- Переменные:
  - Глобальные переменные размещаются в секции статических данных `.data` по фиксированным адресам
  - Локальные переменные функций, обработчиков и блоков основного кода размещаются на стеке по фиксированным смещениям относительно `FP`
  - Место под локальные переменные резервируется при входе, инициализаторы выполняются при достижении объявления
  - Результат выражения находится в `r1`. Перед вычислением правого операнда левый сохраняется на стек, затем извлекается в `r5`
- Массивы:
  - Конструкция `var buf = arr(N);` выделяет блок из `N * 4` байт в секции `.data`
  - Доступ по индексу `buf[i]` вычисляет адрес как `buf + i*4`
  - Каждое объявление получает свой блок. Повторное выполнение объявления возвращает тот же адрес без повторного обнуления
- Стек:
  - Область памяти, располагается в памяти данных
  - Растет вниз
  - Заход `SP` в статические данные завершает модель с ошибкой переполнения стека
- Функции:
  - До четырех аргументов передаются через `r1 - r4`, больше четырех - все через стек
  - Аргументы вычисляются слева направо с временным сохранением на стеке. Стековые аргументы освобождает вызывающая функция
  - До четырех параметров копируются в `r9 - r12`, прежние значения этих регистров сохраняются. При большем числе параметры остаются на стеке
  - Каждая функция сохраняет `r15` и прежний `FP`: по `FP` находится старый `FP`, по `FP + 4` - адрес возврата
  - Последний стековый аргумент находится по `FP + 8`, предыдущий - по `FP + 12`. Локальные переменные - по отрицательным смещениям
- Прерывания:
  - Принимаются между инструкциями при `IE = 1`. Приоритет выше у меньшего номера
  - В отдельном такте `INTERRUPT` процессор сохраняет адрес следующей инструкции в `EPC`, сбрасывает `IE` и устанавливает `PC` на вектор
  - Пролог обработчика сохраняет `r1 - r12`, `r14`, `r15`, эпилог восстанавливает их и выполняет `IRET`
  - `IRET` восстанавливает `PC` и устанавливает `IE = 1`. Вложенные прерывания не поддерживаются
  - `EI/DI` доступны только в ISA. Стартовый код устанавливает `FP`, резервирует локальные переменные и выполняет `EI`

### Ввод-вывод

- Вход задается расписанием `[такт, порт, ASCII-символ]`, такты нумеруются с 1
- Входной порт `N` вызывает `handler N`. Дубликат обработчика или событие без обработчика - ошибка
- У каждого входного устройства один регистр данных и флаг `ready`. Запрос IRQ активен, пока `ready = 1`
- `IN` читает байт и сбрасывает `ready`. Чтение при `ready = 0` завершает модель с ошибкой
- Если до чтения поступает новый байт, он отбрасывается с записью в журнал. Старый байт сохраняется
- События поступают и при `IE = 0`. На каждом такте сначала поступают события, затем выполняются действия процессора
- События одного такта обрабатываются в порядке записей расписания. Источник IRQ выбирается в такте `INTERRUPT`
- Выходной порт один, номер 1, прерываний вывода нет. `OUT` выводит младший байт как ASCII-символ, значение байта выше 127 - ошибка
- Конец расписания не завершает программу. В конце основного кода выполняется `HALT`

## Система команд

- Архитектура: RISC
- Фиксированная длина всех инструкций: 32 бита
- Load-Store: арифметические и логические операции выполняются только над регистрами процессора. Доступ к памяти только через специальные команды
- Ввод-вывод: Port-mapped - взаимодействие с внешними устройствами через отдельные инструкции с явной адресацией портов
- Порядок байт в машинном слове: Little-Endian

### Форматы машинных инструкций

Все инструкции кодируются одним 32-битным словом и делятся на три базовых формата:
```
31        26 25    22 21    18 17    14 13                            0
+-----------+--------+--------+--------+------------------------------+
| Opcode(6) | Rd(4)  | Rs1(4) | Rs2(4) |           Unused(14)         |  R-type
+-----------+--------+--------+--------+------------------------------+

31        26 25    22 21    18 17                                     0
+-----------+--------+--------+---------------------------------------+
| Opcode(6) | Rd(4)  | Rs1(4) |            Immediate(18)              |  I-type
+-----------+--------+--------+---------------------------------------+

31        26 25                                                       0
+-----------+---------------------------------------------------------+
| Opcode(6) |                       Address(26)                       |  J-type
+-----------+---------------------------------------------------------+
```

- Opcode (биты 31–26, 6 бит): код операции (поддерживает до 64 инструкций)
- Rd (биты 25–22, 4 бита): номер регистра назначения. В `SW`, `OUT` и условных переходах служит регистром-источником
- Rs1 (биты 21–18, 4 бита): номер первого регистра-источника / базовый регистр адреса памяти
- Rs2 (биты 17–14, 4 бита): номер второго регистра-источника (только для R-type)
- Immediate (биты 17–0, 18 бит): константа со знаком в дополнительном коде, смещение адреса или номер порта ввода-вывода
- Address (биты 25–0, 26 бит): абсолютный адрес целевой команды в памяти инструкций

Неиспользуемые поля заполняются нулями. Адреса переходов кратны 4. Смещение условного перехода отсчитывается в байтах от адреса текущей инструкции; если условие ложно, выполняется следующая инструкция по адресу `PC + 4`.

### Цикл исполнения инструкций (FSM Control Unit)

Выполнение любой инструкции процессором разбито на такты:

1. `FETCH` (1 такт): выборка 32-битной инструкции из памяти команд по адресу `PC`
2. `DECODE` (1 такт): декодирование полей `Opcode`, `Rd`, `Rs1`, `Rs2`, `Immediate` и чтение операндов из регистрового файла
3. `EXECUTE` (1 такт, опционально): вычисление результата в АЛУ, расчет адреса памяти, проверка условия перехода либо подготовка обращения к порту
4. `MEMORY` (1 такт, опционально): обращение к памяти данных (`LW`, `SW`) либо портам (`IN`, `OUT`)
5. `WRITEBACK` (1 такт, опционально): запись вычисленного значения или прочитанных данных в целевой регистр `Rd`

`EI`, `DI` и `HALT` завершаются в `DECODE`. У `CALL` переход выполняется в `EXECUTE`, запись сохраненного адреса возврата в `r15` - в `WRITEBACK`. Такт входа в прерывание `INTERRUPT` не входит в длительность инструкции.

| I | `SW`   | `0x12` | `Rd, Rs1, Imm` | 4 | `DataMem32[Rs1 + Imm] <- Rd` (сохранение 32 бит) |
| I | `BEQ`  | `0x15` | `Rs1, Rd, Imm` | 3 | Если `Rs1 == Rd`, то `PC <- PC + Imm` |
| I | `BNE`  | `0x16` | `Rs1, Rd, Imm` | 3 | Если `Rs1 != Rd`, то `PC <- PC + Imm` |
| I | `BLT`  | `0x17` | `Rs1, Rd, Imm` | 3 | Если `Rs1 < Rd`, то `PC <- PC + Imm` |
| I | `BGE`  | `0x18` | `Rs1, Rd, Imm` | 3 | Если `Rs1 >= Rd`, то `PC <- PC + Imm` |
| I | `IN`   | `0x19` | `Rd, Port`     | 5 | `Rd <- PortIn[Port]; ready <- 0` |
| I | `OUT`  | `0x1A` | `Rd, Port`     | 4 | `PortOut[Port] <- Rd & 0xFF` (вывод ASCII-символа) |
| J | `JMP`  | `0x20` | `Addr`         | 3 | `PC <- Addr` (безусловный переход) |
| J | `CALL` | `0x21` | `Addr`         | 4 | `r15 <- PC + 4; PC <- Addr` (вызов функции) |
| J | `RET`  | `0x22` | -              | 3 | `PC <- r15` (возврат из функции) |
| J | `IRET` | `0x23` | -              | 3 | `PC <- EPC; IE <- 1` (возврат из прерывания) |
| J | `HALT` | `0x24` | -              | 2 | Останов процессора |
| J | `EI`   | `0x25` | -              | 2 | `IE <- 1` |
| J | `DI`   | `0x26` | -              | 2 | `IE <- 0` |

Невыровненный доступ, выход за границы памяти и неизвестный opcode завершают модель с ошибкой. Эффективный адрес `LW/SW` вычисляется как `(Rs1 + Imm) mod 2^32` с расширением знака Immediate.
